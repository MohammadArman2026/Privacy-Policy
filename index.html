About MarkRead

MarkRead — Markdown Reader is an Android app that lists Markdown notes from folders you choose, and opens them for reading. You can mark a note read or unread, resume an unfinished note, and save a PDF copy of an open note.

The name shown on the device is MarkRead. The Android application ID is com.reyaz.markread.

MarkRead does not create user accounts and does not upload your notes to a server operated by the developer. The library, search, and reading record stay on the device, except for the cases described in this policy: a font-file request handled by Google Play services, and a link or PDF that you choose to open in another app.

Information we collect

In this policy, “collect” means information the app accesses, stores, or processes. Most of that information stays on your device. Each item below states whether a copy leaves the device.

Markdown files on your device

What data is involved
Files whose names end in .md or .markdown. For each file the app can read the file name, size, last-modified time, content URI, and file path. When you open a note, the app reads the file’s text. When you export a PDF, the app reads that text again on the device to build the PDF.
Whether it is collected
The app accesses these files on the device. It does not collect them onto a developer server.
Whether it is stored
The note text is not copied into the app database. The app stores a local catalog of file details. The original Markdown file stays where it already was. A PDF you export is a new file in Downloads.
Whether it leaves the device
Note text, file names, and paths are not sent to the developer. If you tap a web link in a note, MarkRead hands that address to another app you choose, usually a browser. If you open an exported PDF from the download notification, MarkRead hands that PDF to another app you choose.
Why it is used
To list your notes, open a note, show its contents, and create a PDF when you ask for one.
Where it is stored
Catalog details are in a private database named markdownone.db. The Markdown file stays in the folder you granted. On Android 10 and later, an exported PDF is written to Downloads. On older Android versions, the PDF is kept in the app’s private files and can be opened from the download notification.
Whether it is shared, and who receives it
It is not shared with the developer, an analytics service, or an advertising service. A browser or PDF app receives a link or a PDF only when you choose to open one.
How long it is retained
The Markdown file remains until you delete it. The catalog row remains until you delete that note in MarkRead, a library refresh no longer sees the file, you clear MarkRead’s storage, or you uninstall MarkRead. An exported PDF remains in Downloads until you delete that PDF. Deleting a note in MarkRead does not delete a PDF already saved from it.
How you can delete it
On the document list, swipe a note and choose Delete. That deletes the Markdown file from device storage and removes its catalog row. Delete exported PDFs from the device’s Downloads or Files app. Clearing MarkRead’s storage, or uninstalling MarkRead, removes the catalog and does not remove Markdown files or PDFs that remain in shared storage.

Storage access used to find those files

What data is involved
MarkRead does not request All files access and does not scan the whole device. It asks you to choose one or more folders with the system folder picker. The addresses of those folders are saved on the device so later launches can open them again.
What the scan covers
Only the folders you grant. Inside each folder, the app looks up to eight directory levels deep for files named .md or .markdown. It skips hidden folders and folders named android, cache, tmp, temp, .thumbnails, and lost.dir. It does not read other file types.
Whether it is collected or leaves the device
No. Choosing a folder does not send your files to the developer.
Why it is used
To list, open, and delete Markdown notes inside the folders you selected.
Where it is stored and who receives it
The granted folder addresses are stored in private app preferences named markdown_granted_folders. File details from the scan are stored only in the on-device catalog. No third party receives the scan.
How long it is retained, and how you can delete it
The folder grants stay until you clear MarkRead’s storage or uninstall the app. You can decline the folder picker. The catalog created from a scan follows the retention rules for Markdown files above.

Reading activity stored on the device

What data is involved
For each note in the catalog, the app can store whether you marked it read, when you last opened it, when it entered the recent list, a heading identifier and position used to resume reading, and the time the file was indexed.
Whether it is collected
It is created on the device. It is not collected by a server.
Whether it is stored
Yes, in markdownone.db in the app’s private storage.
Whether it leaves the device
No.
Why it is used
To filter All, Recent, Read, and Unread, to keep up to ten unfinished notes in Recent, to restore your place when you reopen an unfinished note, and to mark a note read when you reach the end.
Whether it is shared, and who receives it
It is not shared. No third party receives it.
How long it is retained
Until you delete that note in the app, a library refresh drops the file because it is no longer found, you clear MarkRead’s storage, or you uninstall the app. A refresh that still finds the same file keeps the reading record when the file address matches, or when the file name and size match.
How you can delete it
Delete the note in MarkRead, clear MarkRead’s storage, or uninstall the app. Marking a note unread clears the read flag and keeps the catalog row.

First-launch flag

What data is involved
A yes-or-no value named isFirstLaunch in a private preferences file named markdown_one_launch. It is not your name, account, or a device identifier.
Whether it is collected
No. It stays on the device.
Whether it is stored
Yes, in app-private SharedPreferences.
Whether it leaves the device
No.
Why it is used
So the first launch can scan for Markdown files before opening the library. After that scan, the app sets the flag to show that the first launch is finished.
Whether it is shared, and who receives it
It is not shared.
How long it is retained
Until you clear MarkRead’s storage or uninstall the app. The app does not offer a separate control to reset this flag.
How you can delete it
Clear MarkRead’s storage, or uninstall MarkRead.

Search text

What data is involved
The text you type into the library search field.
Whether it is collected
No.
Whether it is stored
It is held in memory while the library screen is open. It is not written to the database or to preferences.
Whether it leaves the device
No.
Why it is used
To filter the catalog by file name. Search does not read note contents and does not send the query anywhere.
Where it is stored, and who receives it
Only in memory on the device. It is not shared.
How long it is retained
Until you change or clear the field, or you leave the app. It is not kept after that.
How you can delete it
Clear the search field.

PDF export and its notification

What data is involved
A PDF created on the device from the open note and saved in Downloads. The app can show a local notification with the PDF file name and a status such as downloading, saved, or failed. On Android 13 and later, the app asks for notification permission when you start an export.
Whether it is collected
No. The PDF is written on the device. The notification is shown by the device. MarkRead does not use a push-notification service.
Whether it is stored
On Android 10 and later, the PDF is stored in Downloads. On older Android versions, it is stored in the app’s private files. While the export job runs, the app’s background work scheduler keeps that job’s document id, file name, and file address in private app storage.
Whether it leaves the device
The app does not upload the PDF. If you tap the finished notification, the device opens a chooser so you can view the PDF in another app. That other app then receives the PDF.
Why it is used
To give you a PDF copy when you choose Download as PDF, and to show whether that save is running, finished, or failed.
Whether it is shared, and who receives it
Only the app you pick from the chooser receives the PDF, and only if you open it. The developer does not receive it.
How long it is retained
On Android 10 and later, the PDF stays in Downloads until you delete it. On older Android versions, it stays until you clear MarkRead’s storage or uninstall the app. The export job details stay until the job finishes or the system discards it. The notification stays until you dismiss it or the system removes it.
How you can delete it
On Android 10 and later, delete the PDF in Downloads or Files. On older Android versions, clear MarkRead’s storage or uninstall the app. Dismiss the notification. Denying notification permission stops these notifications. The export still runs after you answer that permission prompt. MarkRead has no separate control that deletes a PDF already saved to Downloads.

Font request handled by Google Play services

What data is involved
MarkRead asks the Google Play services font provider on the device for the font families Newsreader, Inter, and JetBrains Mono, including the weights and italic styles the interface uses. If those font files are not already on the device, Google Play services may download them from Google.
Whether it is collected
MarkRead does not collect this request onto its own server. Google may receive the font download request from Google Play services. That request identifies the font family, weight, and style. It does not include your notes, file names, file paths, reading progress, or search text.
Whether it is stored
MarkRead does not keep a server copy of the request. Google Play services may cache the font files on the device.
Whether it leaves the device
The font-file request can leave the device, sent by Google Play services to Google, when the fonts are not already cached. Your note contents do not leave the device as part of that request.
Why it is used
To display the app’s reading and interface typefaces.
Who receives it
Google, through Google Play services, when a font file has to be downloaded. The developer does not receive the request. Google’s handling of data it receives is described in Google’s Privacy Policy.
How long it is retained
MarkRead does not set a retention period for any copy Google keeps of a font request. Font files cached by Google Play services remain under that service’s control. Uninstalling MarkRead does not by itself delete fonts cached for the device by Google Play services.
How you can limit it
The app does not include a switch that turns this font request off. The app declares internet permission. MarkRead’s own code does not include a networking client and does not call a server operated by the developer.

Diagnostic messages on the device

What data is involved
The app writes a local log entry with the count of Markdown files it indexed. If a folder scan fails, or if deleting a file through the system fails, it writes a local warning. A delete-failure log can include the file’s content address.
Whether it is collected
No. The app does not include a crash-reporting or analytics SDK, and it does not transmit these logs.
Whether it is stored
They are written to the device log, which Android manages.
Whether it leaves the device
Not by MarkRead. If you later choose to send an Android bug report, the system’s bug-report flow can include device logs. MarkRead does not start that flow.
Why it is used
To record scan and delete problems on the device while the app is running.
Who receives it
No third party receives these logs from MarkRead.
How long it is retained, and how you can delete it
Android clears the device log on its own schedule, and a restart typically clears it. MarkRead does not offer a log viewer or a log-delete button.

Information we do not collect

Inspection of the app source shows that MarkRead does not request or use the following, and does not include SDKs that do:

  • Account registration, sign-in, passwords, or profile details
  • Your name, email address, phone number, or contacts
  • Location
  • Camera or microphone
  • Advertising ID
  • Photos, video, or audio as a media library. The storage scan looks for Markdown file names.
  • Analytics events or crash reports sent to a reporting service
  • Advertising
  • Payment or purchase history
  • A WebView. The app also does not download images referenced inside a Markdown note. Image markup is shown as its text label.

Library search compares what you type with file names only. It does not index note text for search.

The app manifest does not declare All files access, broad storage access, location, camera, microphone, photo, video, or audio permissions. Internet permission is declared. The app’s own code does not use it to contact a developer server.

How we use information

  • File details are used to list Markdown notes and to refresh that list.
  • Note text is used to display the note you open and to build a PDF when you choose Download as PDF.
  • Reading flags and resume position are used for the Read, Unread, and Recent filters, and to reopen an unfinished note near where you left it.
  • The first-launch flag is used so the first launch can scan before showing the library.
  • Search text is used only to filter file names on the device.
  • Notification permission is used to show the status of a PDF export on the device.
  • The font request is used to load Newsreader, Inter, and JetBrains Mono.
  • A link you tap is used only to open that address in another app.

MarkRead does not use this information for advertising, sale of personal information, cross-app tracking, credit decisions, or account profiling. There is no account to profile.

Data storage

  • The catalog and reading record are stored in the private database markdownone.db.
  • The first-launch flag is stored in private SharedPreferences named markdown_one_launch.
  • The addresses of folders you grant are stored in private SharedPreferences named markdown_granted_folders.
  • Search text is kept in memory for the current library screen.
  • Note text is read into memory while a note is open or while a PDF is being built. It is not written into the catalog database.
  • On Android 10 and later, exported PDFs are stored in Downloads. On older Android versions, they are stored in the app’s private files.
  • A PDF export job’s document id, file name, and file address are stored in private app storage until the job finishes.
  • Android backup of MarkRead data is turned off. Cloud backup and device-to-device transfer rules exclude the app’s files, database, preferences, and external data.

Data sharing and third parties

The developer does not sell your information and does not transfer your notes, catalog, or reading activity to a data broker, advertiser, or analytics company.

Information moves outside MarkRead only in these cases:

  • Google Play services font provider. Google may receive a request for the font files named above when they are not already on the device. That request does not include your notes. See Google’s Privacy Policy.
  • An app you choose. Tapping a link opens it in a browser app, if one is installed. Opening a finished PDF uses a system chooser. MarkRead does not send either action to an analytics or advertising service.

These libraries run on the device and do not receive your notes as a network service: AndroidX, Jetpack Compose, Room, WorkManager, Dagger Hilt, Kotlin coroutines, kotlinx.serialization, and CommonMark. They parse, store, or schedule work locally. They are not analytics, advertising, or sign-in services.

The app source does not include Firebase, Crashlytics, Google Analytics, AdMob, or a sign-in SDK, and it does not include a Firebase configuration file.

Data security

  • The catalog database and the first-launch preference are stored in the app’s private storage. Other apps cannot read that storage by default.
  • Android backup of this app’s data is disabled, including cloud backup and device-to-device transfer of the app’s files, database, and preferences.
  • The file provider used so another app can read a PDF on older Android versions is not exported.
  • MarkRead does not add its own encryption layer to the local database. That database is protected by Android’s app sandbox and your device lock.
  • Markdown files and exported PDFs in shared storage, such as Downloads, are ordinary files. Another app that you have allowed to read storage can read them. MarkRead does not encrypt those shared files.
  • The developer does not hold a server copy of your notes.

Data retention

MarkRead does not retain your notes or reading activity on a server, because it does not send them to one. On the device:

  • Catalog and reading record: kept until the note is deleted in the app, a refresh no longer finds the file, you clear app storage, or you uninstall the app.
  • First-launch flag: kept until you clear app storage or uninstall the app.
  • Search text: kept in memory only while you are using that search.
  • Open note text: kept in memory while the note is open or while a PDF is being built.
  • Exported PDF: on Android 10 and later, kept in Downloads until you delete the file. On older Android versions, kept in the app’s private files until you clear storage or uninstall.
  • PDF job details: kept on the device until the job completes or is discarded.
  • Font files cached by Google Play services: retained by Google Play services, not by a schedule set in MarkRead.

To remove MarkRead’s private data, including the catalog and the saved folder grants, open Android Settings, then Apps, then MarkRead, then Storage, and clear storage. You can also uninstall MarkRead. Those steps do not delete Markdown files that remain in the folders you chose. On Android 10 and later, a PDF already saved in Downloads also remains until you delete that file. Use Delete on a note to remove that Markdown file from its folder.

Account creation and deletion

MarkRead does not provide account creation. It does not ask you to register, sign in, or provide an email address or password, and it does not create a user id.

The app does not maintain user accounts. There is no account to delete inside the app or on a website. This page is a privacy policy. It is not an account-deletion page.

You can still remove the app’s local data by clearing MarkRead’s storage or uninstalling it, and you can delete individual notes from the document list.

User choices and rights

  • Folders. You choose which folders MarkRead may read. If you do not choose a folder, the library stays empty. Clearing MarkRead’s storage removes those folder grants.
  • Notifications. You can deny notification permission. MarkRead then does not show PDF export notifications. You can turn the permission off in Android Settings.
  • Notes. You choose which Markdown files to keep on the device. Swipe Delete removes a note and its catalog row.
  • Read state. You can mark a note read or unread.
  • Links and PDFs. You choose whether to tap a link or open a PDF in another app.
  • App-private data. Clear MarkRead’s storage or uninstall the app to remove the catalog, reading record, and first-launch flag.

The developer does not hold a remote copy of your notes or reading history. A request to access, correct, or erase a server copy cannot return or delete one, because none is kept. Email markread.support@gmail.com if you believe something different has happened, or if the privacy law where you live gives you a right you want to exercise.

Children’s privacy

MarkRead — Markdown Reader is a general-purpose reader for files on a device. It is not directed at children under 13, and it does not knowingly collect personal information from children. The app does not ask for a child’s name, email address, or account.

If you are a parent and you believe a child has sent personal information to the developer about MarkRead, email markread.support@gmail.com.

Third-party services

Google Play services (Google), on-device font provider. Used to obtain the Newsreader, Inter, and JetBrains Mono font files. Google’s processing of a font download is covered by Google’s Privacy Policy.

Other apps on your device that open web links or PDF files. They receive data only after you tap a link or open an exported PDF. Their privacy practices are their own.
